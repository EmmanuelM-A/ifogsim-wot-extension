# Analytical Support Document for Simulation Results

## 1. Introduction

### 1.1 Purpose of the Document

The purpose of this document is to provide guidance on understanding and interpreting the simulation results produced by 
iFogSim. The document will help you to analyse these outputs, and gain a better insight into the performance of your 
IoT applications and make more informed decisions to optimize your system architecture, resource allocation, 
configurations and overall efficiency. 

### 1.2 Scope

This document focuses exclusively on the default simulation results generated by iFogSim, excluding any custom 
performance metrics. These results provide insights into the performance and efficiency of IoT applications. The key 
metrics analyzed in this document include:

- Execution Time – Total duration required to complete the simulation.

- Application Loop Delays – Time taken for data to travel through the IoT system.

- Tuple Execution Delays – Processing time of individual data tuples at different system nodes.

- Energy Consumption per Device – Power usage of each simulated device.

- Total Network Usage – Data transmitted across the network during simulation.

- Cloud Execution Cost – Estimated cost of cloud resource usage during execution.

Each of these metrics will be explored in detail in later sections, providing guidance on how to interpret them and how 
they impact IoT system performance.

## 2. Overview of Simulation Results

### 2.1 Types of Results

The simulation results are produced and calculated by iFogSim's simulation mechanism and is based on the constructed
application's topology and device and connection configurations. The system's topology follows this hierarchical
structure:

CLOUD <---> EDGE NODES <----> Virtual Devices (Sensors and Actuators)

The key performance indicators (KPIs) extracted from the simulation results include execution time, network delays, 
energy consumption, and cloud usage.

Additionally, the simulation tracks two types of Application Loops (AppLoops):

- Regular App Loops – Measure the standard data flow across the system. Below is an example of what a regular app loop
looks like:

`[SOURCE, N PROCESSING MODULES, DESTINATION] ---> N ms`

- Event-Triggered App Loops – Specifically track the response time of workflows initiated by Web of Things (WoT) event 
nodes. These measure delays from event initiation to final destination. Event AppLoops can be identified by the 
presence of the processing module `EventProcessor` in an app loop as shown below:

`[SOURCE, EventProcessor, DESTINATION] ---> N ms`

### 2.2 Key Metrics for Optimization

When optimizing IoT applications, the following key metrics should be carefully analyzed to enhance performance, 
scalability, and cost-efficiency:

- Application Loops (AppLoops) – Measures the time taken for data to travel from source devices (e.g., sensors), 
through processing nodes, and back to actuators or end-user devices. This is crucial for assessing the responsiveness 
of time-sensitive IoT applications.

- Tuple Execution Delays – Represents the time required to process individual data tuples at different fog devices or 
cloud nodes. This helps identify processing bottlenecks and can be analyzed per device or application module.

- Total Network Usage – Quantifies the data transmitted across the network during the simulation. Monitoring network
usage helps optimize communication efficiency and reduce unnecessary data flow.

- Cloud Execution Cost – Represents the estimated financial cost of using cloud resources, including processing, 
storage, and data transmission. Understanding this metric helps in optimizing cloud-based deployments for 
cost-effective operation.
